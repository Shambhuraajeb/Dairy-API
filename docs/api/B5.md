# B5 API: Employees/HR, Reports, Notifications, Administration, Profile

Envelope, errors, auth as in `foundation.md`. Lists: `GET ...?page&pageSize&search&sortBy&sortDir&<filters>` -> `data = { items, total, page, pageSize, totalPages }`.
Request dates: `"2026-10-05"` (or ISO datetime). Response dates in DTOs: ISO datetime (`"2026-10-05T00:00:00"`); take 10 chars for date-only fields. Report rows use plain `"yyyy-MM-dd"` strings.
Perm column: `a|b` = any of. Business-rule failures -> 422, duplicates -> 409, missing -> 404, bad fields -> 400 with `errors[{field,message}]`.
Audit rows are written for every create/update/approve/payment/settings/role/permission change.

## 1. Designations `/api/designations`
Designation: `{ id, name, department, description, isActive, employeeCount }` (employeeCount = active employees).
| Method URL | Perm | Query / body | Data |
|---|---|---|---|
| GET `/api/designations` | employee.view | `search, isActive, sortBy(id\|name\|department\|isActive)` | Paged Designation |
| GET `/api/designations/{id}` | employee.view | | Designation |
| POST `/api/designations` | employee.create | `{ name*, department, description }` | 201 Designation (409 duplicate name) |
| PUT `/api/designations/{id}` | employee.update | `{ name*, department, description, isActive? }` | Designation (422 deactivating one with active employees) |
| DELETE `/api/designations/{id}` | employee.update | | null (soft deactivate; 422 if active employees) |

## 2. Employees `/api/employees`
Employee: `{ id, employeeCode, fullName, gender, dateOfBirth, mobile, email, addressLine, city, designationId, designationName, branchId, branchName, joinDate, exitDate, basicSalary, defaultAllowances, defaultDeductions, bankName, bankAccountNo, ifscCode, aadhaarNo, panNo, emergencyContact, status(Active|Inactive|Terminated), isActive, createdDate }`
| Method URL | Perm | Query / body | Data |
|---|---|---|---|
| GET `/api/employees` | employee.view | `designationId, status, branchId, search(name/code/mobile/email), sortBy(id\|employeeCode\|fullName\|mobile\|designationName\|joinDate\|basicSalary\|status\|createdDate)` | Paged Employee |
| GET `/api/employees/{id}` | employee.view | | Employee |
| POST `/api/employees` | employee.create | `{ employeeCode?, fullName*, gender(Male\|Female\|Other), dateOfBirth, mobile(10-13 digits), email, addressLine, city, designationId*, branchId, joinDate(default today), basicSalary, defaultAllowances, defaultDeductions, bankName, bankAccountNo, ifscCode, aadhaarNo(12 digits), panNo, emergencyContact }` | 201 Employee. | PUT `/api/employees/{id}` | employee.update | same body without `employeeCode`, plus `exitDate` (full state: omitted optional fields are cleared) | Employee |

## 3. Attendance `/api/attendance`
Attendance: `{ id, employeeId, employeeCode, employeeName, attendanceDate, checkIn, checkOut, workedHours, status(Present|Absent|HalfDay|Leave), remarks }`
Users without `attendance.manage` AND `employee.view` only see their own employee's rows (needs a linked `employeeId`).
| Method URL | Perm | Query / body | Data |
|---|---|---|---|
| GET `/api/attendance` | attendance.view | `date` (single day) or `from,to`, `employeeId, status, search, sortBy(id\|attendanceDate\|employeeName\|employeeCode\|status\|workedHours)` | Paged Attendance |
| GET `/api/attendance/sheet` | attendance.view (HR only) | `date`(default today), `designationId` | `[{ employeeId, employeeCode, employeeName, designationName, attendanceId, status, checkIn, checkOut, workedHours, remarks }]` all active employees; status null = not marked |
| POST `/api/attendance` | attendance.manage | `{ employeeId*, date*, status*, checkIn, checkOut, remarks }` (checkIn/out = `"HH:mm"` or ISO datetime; upsert per employee+date; workedHours computed; no future dates) | Attendance |
| POST `/api/attendance/bulk` | attendance.manage | `{ date*, entries*: [{ employeeId, status, checkIn, checkOut, remarks }] }` (max 1000, atomic) | `{ date, saved }` |

| Method URL | Perm | Query / body | Data |
|---|---|---|---|

| GET `/api/leave-requests/{id}` | leave.view | | LeaveRequest |
| POST `/api/leave-requests` | leave.create | `{ employeeId?, leaveType*, fromDate*, toDate*, days?(multiple of 0.5, default = calendar days), reason }` blank employeeId = caller's own `EmployeeId` (422 if not linked); filing for someone else needs `leave.approve`; 422 on overlap with Pending/Approved | 201 LeaveRequest (Pending) |

## 6. Reports `/api/reports` (all need `report.view`)
- `GET /api/reports/catalog` -> `[{ code, name, group, description, filters: string[], columns: [{ key, label, type }] }]` (19 reports). `type` = text|number|money|date|datetime|boolean. `filters` keys are query-string names.
- `GET /api/reports/{code}?from&to&branchId&collectionCenterId&farmerId&customerId&productId&shiftId&itemId&categoryId&status[&format=csv]` -> `data = { code, name, columns:[{key,label,type}], rows:[{ id?, <key>: value, ... }], totals: {<key>: sum} | null, extra: {...} | null }`. Unsupported filters are ignored. `from > to` -> 400. Unknown code -> 404.
- `format=csv`: `text/csv; charset=utf-8` attachment (`{code}-yyyyMMdd-HHmmss.csv`, UTF-8 no BOM, CRLF, header = column labels, quoted/escaped cells, final "Total" row when totals exist).
- Row keys are camelCase; rows may contain extra keys not listed in `columns` (e.g. `id`, `farmerId`).

| code | group | source | filters | row keys (columns) |
|---|---|---|---|---|
| daily-collection | Collection | sp_GetCollectionReport Daily | from,to,branchId,collectionCenterId,farmerId,shiftId,status | collectionDate, totalCollections, farmerCount, totalQuantity, acceptedQuantity, rejectedQuantity, avgFat, avgSnf, totalAmount, pendingCount, approvedCount, rejectedCount |
| shift-collection | Collection | Shift | same | collectionDate, shiftName, collectionCenterName + the daily keys |
| farmer-collection | Collection | Farmer | same | farmerCode, farmerName, totalCollections, totalQuantity, acceptedQuantity, rejectedQuantity, avgFat, avgSnf, avgRate, totalAmount, pending/approved/rejectedCount |
| milk-quality | Collection | Quality | same | collectionNumber, collectionDate, shiftName, collectionCenterName, farmerCode, farmerName, quantityLiters, fat, snf, clr, temperature, acidity, waterAdded, starchDetected, ureaDetected, neutralizerDetected, antibioticDetected, qualityResult, failureReason, status |
| rejected-milk | Collection | Rejected | same minus status | rejectionDate, collectionNumber, collectionDate, shiftName, collectionCenterName, farmerCode, farmerName, reasonCode, reason, quantityLiters, disposalMethod, collectionStatus |
| farmer-settlement | Farmer Payments | sp_GetFarmerPaymentReport Settlement | from,to,farmerId,status | paymentNumber, paymentDate, periodFrom, periodTo, farmerCode, farmerName, totalCollections, totalQuantity, grossAmount, bonusAmount, penaltyAmount, deductionAmount, netPayable, paidAmount, balanceAmount, status |
| farmer-outstanding | Farmer Payments | Outstanding | from,to,farmerId | farmerCode, farmerName, unsettledQuantity, unsettledAmount, pendingPaymentBalance, payableToFarmer, advanceBalance, loanOutstanding, recoverableFromFarmer, netOutstanding |
| animal-health | Animals | inline SQL (AnimalHealthRecord) | from,to (RecordDate),branchId,collectionCenterId,farmerId,status(Open\|Ongoing\|Recovered) | recordDate, tagNumber, animalName, animalType, farmerCode, farmerName, healthCondition, severity, diagnosis, treatment, vetName, cost, status, followUpDate, recoveredDate |
| vaccination-due | Animals | inline SQL (latest dose per animal+vaccine) | `to` = due-until (default today+30d), from, branchId,collectionCenterId,farmerId,status(Due\|Overdue) | tagNumber, animalName, animalType, farmerCode, farmerName, vaccineName, lastVaccinationDate, nextDueDate, daysToDue, dueStatus |
| inventory-stock | Inventory | sp_GetInventoryReport Stock | categoryId(item category),itemId | itemCode, itemName, categoryName, unitName, currentStock, reorderLevel, maxStockLevel, unitCost, stockValue, stockStatus |

| purchase | Inventory | Purchase | from,to,categoryId,itemId | purchaseNumber, purchaseDate, supplierName, itemCode, itemName, categoryName, quantity, receivedQuantity, unitCost, taxAmount, lineTotal, batchNumber, expiryDate, status |
| sales | Sales | sp_GetSalesReport Sales | from,to,customerId,productId,status | orderNumber, deliveryDate, status, source, customerCode, customerName, productCode, productName, quantity, deliveredQuantity, unitPrice, discountAmount, taxAmount, lineTotal, invoiceNumber |
| customer-outstanding | Sales | CustomerOutstanding | same | invoiceNumber, customerCode, customerName, invoiceDate, dueDate, totalAmount, paidAmount, balanceAmount, daysOverdue, status |
| delivery-performance | Sales | DeliveryPerformance | same | driverName, totalDeliveries, delivered, failed, pending, successRate |
| expenses | Finance | sp_GetExpenseReport | from,to,categoryId(expense category),status | expenseNumber, expenseDate, categoryName, amount, paymentModeName, description, payee, branchName, status, approvedDate, rejectionReason |
| revenue | Finance | sp_GetSalesReport Revenue | from,to,customerId,productId,status | reportDate, invoiced, collected, difference |

## 7. Notifications `/api/notifications` (notification.view)
Notification: `{ id, userId, roleId, title, message, severity(info|warning|danger|success), link, isRead, createdDate, readDate }`
Visible rows = addressed to the caller, or broadcast to the caller's role, or global; Super Admin sees all broadcasts. `isRead` on a role broadcast is shared by that role.
| Method URL | Query / body | Data |
|---|---|---|
| GET `/api/notifications` | `unreadOnly(true), severity, search, sortBy(id\|title\|severity\|isRead\|createdDate), sortDir` (default newest first) | Paged Notification |
| GET `/api/notifications/unread-count` | | `{ count }`. Also runs `sp_GenerateAlertNotifications` at most once per 10 minutes (process-wide) so low-stock/expiry/maintenance/vaccination/approval alerts appear. |
| POST `/api/notifications/{id}/read` (alias `/mark-read`) | no body | Notification (404 if not visible) |
| POST `/api/notifications/read-all` (alias `/mark-all-read`) | no body | `{ updated }` |

### Organization (settings.manage); common query `search, isActive, sortBy(id|code|name|city|isActive)`; PUT bodies may include `isActive`
- Dairy `/api/admin/dairy`: GET (paged), GET `{id}`, POST (201), PUT `{id}`. Body `{ code*, name*, ownerName, mobile, email, addressLine, city, state, pincode, gstNumber, licenseNo, registrationNo, isActive? }`. DTO = body fields + `id` (code stored upper-case).
- Branches `/api/admin/branches` (+ `dairyId` filter): body `{ dairyId*, code*, name*, addressLine, city, state, pincode, mobile, email, managerName, isActive? }`; DTO adds `id, dairyName`. Deactivating a branch with active collection centers -> 422.
- Collection centers `/api/admin/collection-centers` (+ `branchId` filter): body `{ branchId*, code*, name*, addressLine, city, pincode, mobile, contactPerson, latitude, longitude, supervisorEmployeeId, capacityLiters, isActive? }`; DTO adds `id, branchName, supervisorName`.
Duplicate code -> 409.
