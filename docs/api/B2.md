# B2 API: milk collection, rate charts, tanks, farmer settlement

Envelope, auth, error codes: see `foundation.md`. Business-rule failures from stored procedures come back as **422** with the SP message
(e.g. "Farmer is not active...", "No active rate chart is effective for this date, center and milk type.").
`PagedResult<T>` = `{ items, total, page, pageSize, totalPages }`. Paged endpoints accept `page, pageSize(<=200), search, sortBy, sortDir(asc|desc)`.
Dates in query/body: `yyyy-MM-dd`. DATE columns in responses are ISO datetimes (`2026-10-05T00:00:00`); TIME columns are `HH:mm:ss`. Decimals are JSON numbers.
Role **Farmer** (has `collection.view` + `payment.view`): lists are forced to own FarmerId, single records of others -> 404; shift dashboard, pending-approvals, milk tanks, pending-farmers -> 403.
Audit: collection adjust/approve/reject and settlement create/approve/pay/cancel are audited inside the stored procedures. Quality test, rate chart and tank changes are audited by the API.

Enums: MilkType `Cow|Buffalo|Mixed` | collection `status` `Pending|Approved|Rejected` | `settlementStatus` `Unsettled|Settled` | `qualityResult` `Pass|Fail` |
rejection `reasonCode` `LowFat|LowSnf|Adulterated|HighTemperature|Sour|Other` | rate chart `status` `Draft|Active|Expired`, `calculationMethod` `Slab|Formula` |
tank `status` `Active|Maintenance|Inactive`, transaction `transactionType` `In|Out|Adjust` | payment `status` `Draft|Approved|Paid|Cancelled` |
deduction `deductionType` `Advance|Loan|Other` | installment `status` `Pending|Partial|Paid`.

## Collection shifts  `/api/collection-shifts`
### GET `/api/collection-shifts` — `collection.view`
Query: `centerId?` (includes shifts with no center = all centers), `isActive?`. Data: `ShiftDto[]` (not paged)
`{ id, collectionCenterId|null, collectionCenterName|null, shiftName("Morning"|"Evening"), startTime("06:00:00"), endTime, description, isActive }`

### GET `/api/collection-shifts/dashboard` — `collection.view`
Query: `date?` (default today), `centerId?`, `shiftId?` (default: current shift by clock, else most recently started). Data:
```
{ date, collectionCenterId|null, shiftId|null, shiftName|null, startTime|null, endTime|null, isCurrentShift,
  totalPendingApprovals,                       // all pending collections (any date) for the center
  summary: ShiftSummary,                       // selected shift name (all centers or centerId) on date
  shifts: ShiftSummary[] }                     // one row per (shift, center) on date, incl. zero rows
ShiftSummary = { shiftId, shiftName, startTime, endTime, collectionCenterId, collectionCenterName,
  farmersServed, totalCollections, totalLiters, acceptedLiters, rejectedLiters, avgFat, avgSnf,
  acceptedCount, rejectedCount, approvedCount, pendingApprovals, totalAmount }
```
(`acceptedLiters` = non-rejected liters, `rejectedLiters` = rejected incl. partial rejections, `totalLiters` = both; avg FAT/SNF weighted by accepted liters.)

## Milk collections  `/api/milk-collections`
### GET `/api/milk-collections` — `collection.view`
Query: `from?, to?` (CollectionDate), `centerId?, shiftId?, farmerId?, status?, settlementStatus?, search?` (collection no / farmer name / farmer code),
`sortBy` = `id|collectionNumber|collectionDate|shiftName|collectionCenterName|farmerCode|farmerName|milkType|quantityLiters|fat|snf|amount|status|settlementStatus|createdDate` (default collectionDate desc). Data `PagedResult<CollectionListItem>`:
`{ id, collectionNumber, collectionDate, shiftId, shiftName, collectionCenterId, collectionCenterName, farmerId, farmerCode, farmerName, milkType, quantityLiters, fat, snf, clr|null, rate(base/liter), finalRate(amount/qty), bonusAmount, penaltyAmount, amount, qualityResult|null, status, settlementStatus, adjustedFlag, farmerPaymentId|null, createdDate }`

### GET `/api/milk-collections/pending-approvals` — `collection.view`
Same query/response as list, `status` forced to `Pending`.

### GET `/api/milk-collections/rate-preview` — `collection.view`
Query: `centerId`(req), `date?`(default today), `milkType?`(default Cow), `fat`(req), `snf`(req), `clr?`, `quantity?`. Data:
`{ rateChartId, rateChartName, rateChartDetailId|null, baseRate, bonus, penalty, finalRate, amount }` (amount = quantity x finalRate). 422 if no effective chart/slab.
(Alias: `GET /api/rate-charts/calculate`, permission `ratechart.view`, same params/response.)

### GET `/api/milk-collections/{id}` — `collection.view`
Data = CollectionListItem plus:
```
temperature|null, canCount|null, rateChartId|null, rateChartName|null, tankId|null, tankName|null,
originalQuantity|null, originalFat|null, originalSnf|null, originalClr|null, originalRate|null, originalAmount|null,   // set once the collection is adjusted/partially rejected
adjustmentReason|null, adjustedBy|null, adjustedByName|null, adjustedDate|null,
approvedBy|null, approvedByName|null, approvedDate|null, rejectedBy|null, rejectedByName|null, rejectedDate|null, rejectionReason|null,
collectedBy|null, collectedByName|null, remarks|null,
qualityTests: [ { id, milkCollectionId, fat, snf, clr, protein, lactose, temperature, acidity, waterAdded, starchDetected, ureaDetected,
                  neutralizerDetected, antibioticDetected, otherAdulteration, result("Pass"|"Fail"), failureReason, testedBy, testedByName, testDate, remarks } ],  // newest first
rateBreakdown: null | { rateChartId, rateChartName, calculationMethod, rateChartDetailId, slabFatFrom, slabFatTo, slabSnfFrom, slabSnfTo,
                        fatUsed, snfUsed, quantityUsed, baseRate, bonus, penalty, finalRate, bonusAmount, penaltyAmount, calculatedDate },
rejections: [ MilkRejection ]
```

### POST `/api/milk-collections` — `collection.create` — 201
Body: `{ collectionDate?(default today, not future), shiftId, collectionCenterId, farmerId, milkType?(default farmer's), quantityLiters(>0), fat, snf, clr?, temperature?, canCount?, milkTankId?, acidity?, waterAdded?(bool), remarks? }`
Ranges: fat/snf 0.1-25, clr 0-60 (the SP additionally enforces the SystemSetting ranges). Data: `{ id, number, rate(final/liter), baseRate, bonusAmount, penaltyAmount, amount, status("Pending"|"Approved" when auto-approve) }`.
Farmer must be Active; rate chart must exist; `waterAdded=true` marks the quality test Fail.

### PUT `/api/milk-collections/{id}` (adjust) — `collection.update`
Body: `{ quantityLiters?, fat?, snf?, clr?, reason(required) }` (null = keep; at least one value). Only Pending/Approved + Unsettled. Rate is recalculated, originals preserved. Data: full collection detail (as GET {id}).

### POST `/api/milk-collections/{id}/approve` — `collection.approve`
No body. Data `{ id, number, status:"Approved" }`. 422 if not Pending or quality = Fail.

### POST `/api/milk-collections/{id}/reject` — `collection.reject`
Body `{ reason(required), quantityLiters? }` (omit = reject whole; value < collected = partial rejection, remainder stays payable). Data `{ id(rejectionId), milkCollectionId, number, status, rejectedQuantity }`.

### POST `/api/milk-collections/bulk-approve` — `collection.approve`
Body `{ ids: [long] }` (1-200). Each id approved independently. Data `{ total, approved, failed, results: [ { id, success, number|null, message } ] }`.

### GET `/api/milk-collections/{id}/quality` — `collection.view`
Data `MilkQualityTest[]` (newest first).

### POST `/api/milk-collections/{id}/quality` — `collection.quality.record`
Collection must be Pending. Updates the latest quality test of the collection or inserts one; sets `qualityResult` on the collection (Fail blocks approval). Does NOT change the payable FAT/SNF (use PUT adjust).
Body: `{ fat?, snf?(default: collection's), clr?, protein?, lactose?, temperature?, acidity?, waterAdded?, starchDetected?, ureaDetected?, neutralizerDetected?, antibioticDetected?, otherAdulteration?, result?("Pass"|"Fail"; default Fail if any adulteration else Pass), failureReason?, remarks? }`
Data: `MilkQualityTest`.

## Rate charts  `/api/rate-charts`
Selection by SP: Active chart for milk type, effective on collection date, center-specific before global, latest effectiveFrom wins.
### GET `/api/rate-charts` — `ratechart.view`
Query: `milkType?, status?, centerId?` (charts applicable to that center: its own + all-center charts), `isActive?`, `search?`(name), `sortBy` = `id|name|milkType|collectionCenterName|effectiveFrom|effectiveTo|status|createdDate` (default effectiveFrom desc). Data `PagedResult<RateChartListItem>`:
`{ id, name, milkType, collectionCenterId|null, collectionCenterName|null, effectiveFrom, effectiveTo|null, status, calculationMethod, baseRatePerLiter, baseFat, baseSnf, fatRatePerPoint, snfRatePerPoint, minRatePerLiter, maxRatePerLiter|null, detailCount, activatedDate|null, isActive, createdDate }`

### GET `/api/rate-charts/{id}` — `ratechart.view`
Data = RateChartListItem plus `bonusMinFat, bonusMinSnf, qualityBonusPerLiter, penaltyBelowFat, penaltyBelowSnf, qualityPenaltyPerLiter, description, activatedBy,`
`details: [ { id, fatFrom, fatTo, snfFrom, snfTo, rate, bonusPerLiter, penaltyPerLiter } ]`.

### POST `/api/rate-charts` — `ratechart.manage` — 201 (creates a **Draft**); PUT `/api/rate-charts/{id}` — `ratechart.manage` (Draft only; replaces header and all details)
Same body for both:
```
{ name, milkType, collectionCenterId?(null = all centers), effectiveFrom, effectiveTo?, calculationMethod("Slab"|"Formula"),
  baseRatePerLiter, baseFat, baseSnf, fatRatePerPoint, snfRatePerPoint, minRatePerLiter, maxRatePerLiter?,   // Formula: rate = base + (fat-baseFat)*fatRatePerPoint + (snf-baseSnf)*snfRatePerPoint, clamped to [min,max]
  bonusMinFat?, bonusMinSnf?, qualityBonusPerLiter, penaltyBelowFat?, penaltyBelowSnf?, qualityPenaltyPerLiter, description?,
  details: [ { fatFrom, fatTo, snfFrom, snfTo, rate, bonusPerLiter, penaltyPerLiter } ] }   // Slab only; fatFrom<=fat<fatTo (top slab inclusive); slabs must not overlap
```
Data: full chart (as GET {id}). 400 on overlapping slabs / bad ranges; 422 when editing a non-draft.

### POST `/api/rate-charts/{id}/activate` — `ratechart.manage`
Draft -> Active (requires >=1 slab for Slab, baseRatePerLiter>0 for Formula). Active charts of the same center scope + milk type whose period overlaps are superseded:
those starting before the new chart get `effectiveTo` = day before the new `effectiveFrom` (stay Active so old collections can still be re-rated); those starting on/after it become `Expired`.
Data `{ chart: <full chart>, supersededChartIds: [long] }`.

### DELETE `/api/rate-charts/{id}` — `ratechart.manage`
Draft -> deleted; Active/Expired -> deactivated (`isActive=false`, Active becomes Expired). Data null, message tells which.

## Milk tanks  `/api/milk-tanks`
### GET `/api/milk-tanks` — `collection.view`
Query: `centerId?, status?, isActive?, search?`(code/name), `sortBy` = `id|code|name|collectionCenterName|capacityLiters|currentQuantity|status|createdDate` (default center, name). Data `PagedResult<Tank>`:
`{ id, code, name, collectionCenterId, collectionCenterName, capacityLiters, currentQuantity, availableCapacity, fillPercent, milkType|null, minTemperature, maxTemperature, currentTemperature, status, lastCleanedDate|null, isActive, createdDate }`
### GET `/api/milk-tanks/{id}` — `collection.view` — Data `Tank`
### POST `/api/milk-tanks` — `collection.create` — 201 Data `Tank`
Body `{ code(unique), name, collectionCenterId, capacityLiters(>0), milkType?, minTemperature?, maxTemperature?, currentTemperature? }` (starts empty, status Active). 409 on duplicate code.
### PUT `/api/milk-tanks/{id}` — `collection.update` — Data `Tank`
Body `{ name, collectionCenterId, capacityLiters(>= current quantity), milkType?, minTemperature?, maxTemperature?, currentTemperature?, status, lastCleanedDate?, isActive?(false = deactivate) }`
### GET `/api/milk-tanks/{id}/transactions` — `collection.view`
Query: `from?, to?, type?(In|Out|Adjust)`, `sortBy` = `id|transactionDate|transactionType|quantity|balanceAfter` (default transactionDate desc). Data `PagedResult<TankTxn>`:
`{ id, tankId, transactionType, quantity, balanceAfter, milkCollectionId|null, collectionNumber|null, transactionDate, destination, referenceType, referenceId, remarks, createdBy, createdByName }`
(`In` rows are created by milk collection; rejection/adjustment of a collection also writes rows.)
### POST `/api/milk-tanks/{id}/transactions` — `collection.update` — 201 Data `TankTxn`
Body `{ transactionType("Out"|"Adjust"), quantity, destination?, remarks? }`. Out: positive liters removed (<= current). Adjust: signed delta (result must stay within 0..capacity).

## Farmer settlement  `/api/farmer-settlements`
Only Approved + Unsettled collections are payable; rejected milk is never paid. Flow: create (Draft) -> approve (Approved) -> pay (Paid; partial pay keeps Approved) | cancel (before any payment; releases the collections).
### GET `/api/farmer-settlements/preview` — `payment.view`
Query: `farmerId`(req), `from`(req), `to`(req) (max 366 days). Data:
```
{ summary: { farmerId, farmerCode, farmerName, periodFrom, periodTo, totalCollections, totalQuantity, grossAmount(excl. bonus/penalty), bonusAmount, penaltyAmount,
             pendingAdvanceBalance, loanInstallmentsDue, suggestedAdvanceDeduction, suggestedLoanDeduction, suggestedDeduction,
             netBeforeDeduction(gross+bonus-penalty), netPayable(after suggested deductions) },
  collections: [ { id, collectionNumber, collectionDate, shiftName, collectionCenterName, milkType, quantityLiters, fat, snf, baseRate, finalRate, bonusAmount, penaltyAmount, amount } ],
  advances: [ { id, advanceNumber, advanceDate, amount, recoveredAmount, balanceAmount, recoveryPerSettlement|null, purpose, availableAmount, suggestedRecovery } ],
  loanInstallments: [ { id, farmerLoanId, loanNumber, installmentNo, dueDate, amount, paidAmount, status, dueAmount } ] }
```
### GET `/api/farmer-settlements/pending-farmers` — `payment.view`
Query: `from`(req), `to`(req), `centerId?` (collection center), `search?` (name/code/mobile). Data (plain array, max 1000, by name):
`[ { farmerId, farmerCode, farmerName, mobile, collectionCenterId, collectionCenterName, collectionsCount, totalQuantity, grossAmount, bonusAmount, penaltyAmount, totalAmount(gross+bonus-penalty), firstCollectionDate, lastCollectionDate, pendingAdvanceBalance, loanInstallmentsDue } ]`
### POST `/api/farmer-settlements` — `payment.create` — 201
Body `{ farmerId, from, to, bonusAmount?, penaltyAmount?, advanceDeduction?, includeLoanInstallments?(default true), otherDeduction?, otherDeductionRemarks?(required if otherDeduction>0), paymentModeId?, referenceNo?, remarks? }`
(bonus/penalty are extras added to the per-collection ones; advance deduction is spread oldest advance first; due loan installments are deducted automatically when included.)
Data `{ id, number, netPayable, grossAmount, bonusAmount, penaltyAmount, deductionAmount, status:"Draft" }`.
### POST `/api/farmer-settlements/{id}/approve` — `payment.approve` — Data `{ id, number, status:"Approved", netPayable }` (Draft only)
### POST `/api/farmer-settlements/{id}/pay` — `payment.create`
Body `{ paymentModeId?(default: saved mode), referenceNo?(required for modes that require it), paidAmount?(default: full balance) }`. Approved only; overpayment rejected (unless setting `payment.allowOverpayment`); writes the cash book entry; when fully paid applies advance/loan recoveries.
Data `{ id, number, status("Paid"|"Approved"), paidAmount, balanceAmount, netPayable }`.
### POST `/api/farmer-settlements/{id}/cancel` — `payment.approve`
Body `{ reason(required) }`. Not allowed once paid/partially paid. Data `{ id, number, status:"Cancelled", releasedCollections }`.

## Farmer payments  `/api/farmer-payments`
### GET `/api/farmer-payments` — `payment.view`
Query: `farmerId?, centerId?, status?, from?, to?` (on `paymentDate`), `search?`(payment no / farmer), `sortBy` = `id|paymentNumber|farmerCode|farmerName|paymentDate|periodFrom|periodTo|grossAmount|deductionAmount|netPayable|paidAmount|balanceAmount|status|createdDate` (default paymentDate desc). Data `PagedResult<Payment>`:
`{ id, paymentNumber, farmerId, farmerCode, farmerName, collectionCenterId, collectionCenterName, paymentDate, periodFrom, periodTo, totalCollections, totalQuantity, grossAmount, bonusAmount, penaltyAmount, deductionAmount, netPayable, paidAmount, balanceAmount, status, paymentModeId, paymentModeName, referenceNo, paidDate, approvedDate, createdDate }`
### GET `/api/farmer-payments/{id}` — `payment.view`
Data = Payment plus `bankName, bankAccountMasked, ifscCode, upiId, approvedBy, approvedByName, paidBy, paidByName, cancelledDate, cancelReason, remarks,`
`details: [ { id, milkCollectionId, collectionNumber, collectionDate, shiftName, quantity, rate, bonusAmount, penaltyAmount, amount } ],`
`deductions: [ { id, deductionType, farmerAdvanceId, advanceNumber, farmerLoanId, loanNumber, farmerLoanInstallmentId, installmentNo, amount, remarks } ]`.
