# B3 API: Inventory, Suppliers, Expenses/Cash, Maintenance

Envelope, auth, error codes: see `foundation.md`. All routes need `Authorization: Bearer`. JSON camelCase; dates `YYYY-MM-DD` (or ISO datetime) in/out.
Lists: `GET ...?page&pageSize&search&sortBy&sortDir(asc|desc)&<filters>` -> data `PagedResult<T>` = `{ items, total, page, pageSize, totalPages }`.
Create -> 201, data = DTO (or `{id,...}` where noted). Update -> 200, data = DTO. `isActive:false` on PUT = deactivate (null/omitted = unchanged).
Business-rule failures (stored procedures / services) -> 422 with message; duplicate code -> 409; missing id -> 404.
Units: `/api/inventory/units` is in foundation.md (not repeated). Unit ids for items come from there.

Stock ledger `transactionType` values: `Purchase | Consumption | Adjustment | Return | Sale | Opening` (procedures write Purchase, Consumption, Adjustment). Quantity is signed (+in / -out).
Batch status: `Available | Depleted | Expired | Quarantined`. Purchase status: `Draft | Approved | Received | Cancelled`; paymentStatus `Unpaid | Partial | Paid`.
Item stockStatus: `OutOfStock` (currentStock<=0) | `Low` (reorderLevel>0 and currentStock<=reorderLevel) | `OK`.
Expense status: `Pending | Approved | Rejected`. Cash type: `In | Out`. Equipment status: `Operational | UnderMaintenance | Retired`.
Schedule status: `Active | Paused`. Maintenance type: `Preventive | Corrective | Breakdown`; record status `Completed | InProgress`.

## Item categories `/api/inventory/categories`
- `GET` inventory.view — q: `isActive`; sort: id,code,name,isActive; row `{ id, code, name, description, isActive, itemCount }`
- `GET /{id}` inventory.view
- `POST` inventory.create — `{ code(<=30), name(<=100), description? }` (code and name unique, else 409)
- `PUT /{id}` inventory.update — `{ code, name, description?, isActive? }`

## Items `/api/inventory/items`
- `GET` inventory.view — q: `categoryId, lowStockOnly(bool), isActive`; sort: id,itemCode,name,categoryName,currentStock,reorderLevel,unitCost,stockValue,isActive
  row `{ id, itemCode, name, itemCategoryId, categoryName, unitId, unitName, description, reorderLevel, maxStockLevel, currentStock, unitCost, stockValue, taxPercent, isPerishable, hasExpiry, shelfLifeDays, preferredSupplierId, preferredSupplierName, storageLocation, barcode, isActive, stockStatus }`
- `GET /{id}` inventory.view — row + `{ totalBatches, availableBatches, expiredBatches, nearestExpiryDate, batches: [Batch] }` (Batch shape below)
- `POST` inventory.create — `{ itemCode, name, itemCategoryId, unitId, description?, reorderLevel, maxStockLevel?, unitCost, taxPercent, isPerishable, hasExpiry, shelfLifeDays?, preferredSupplierId?, storageLocation?, barcode? }` -> detail DTO. currentStock starts at 0 (changes only via purchase receipt / consumption / adjustment).
- `PUT /{id}` inventory.update — same body + `isActive?` -> detail DTO

## Suppliers `/api/suppliers`
- `GET` supplier.view — q: `isActive`; sort: id,supplierCode,name,city,isActive,createdDate;
  row `{ id, supplierCode, name, contactPerson, mobile, email, addressLine, city, state, pincode, gstNumber, panNo, paymentTermsDays, isActive, createdDate, purchaseCount, totalPurchased }`
- `GET /{id}` supplier.view
- `POST` supplier.manage — `{ supplierCode(<=30, unique), name, contactPerson?, mobile?(10-13 digits), email?, addressLine?, city?, state?, pincode?, gstNumber?, panNo?, paymentTermsDays(0-365) }`
- `PUT /{id}` supplier.manage — same + `isActive?`

## Batches `GET /api/inventory/batches` (inventory.view)
q: `itemId, expiring(bool), expired(bool), available(bool), days, status`; sort: id,itemName,batchNumber,expiryDate,receivedDate,quantityAvailable,status. Default sort: expiry date ascending (non-expiring last).
`expiring=true`: stock left, not expired, expires within `days` (default setting inventory.expiryAlertDays). `expired=true`: stock left, expiry date passed. `available=true`: stock left, status Available, not expired.
Batch `{ id, inventoryItemId, itemCode, itemName, unitName, batchNumber, supplierId, supplierName, purchaseDetailId, purchaseNumber, manufactureDate, expiryDate, receivedDate, quantityReceived, quantityAvailable, unitCost, stockValue, storageLocation, status, daysToExpiry, isExpired }`

## Purchases `/api/inventory/purchases`
- `GET` purchase.view — q: `supplierId, status, paymentStatus, from, to`(purchase date); sort: id,purchaseNumber,purchaseDate,supplierName,totalAmount,status,paymentStatus,createdDate
  row `{ id, purchaseNumber, supplierId, supplierName, branchId, purchaseDate, expectedDate, supplierInvoiceNo, subTotal, taxAmount, discountAmount, totalAmount, paidAmount, paymentStatus, status, approvedBy, approvedByName, approvedDate, receivedBy, receivedByName, receivedDate, cancelledDate, cancelReason, remarks, createdBy, createdByName, createdDate, lineCount }`
- `GET /{id}` purchase.view — row + `lines: [{ id, purchaseId, inventoryItemId, itemCode, itemName, unitName, quantity, receivedQuantity, unitCost, taxPercent, taxAmount, lineTotal, batchNumber, manufactureDate, expiryDate, remarks }]`
- `POST` purchase.create — `{ supplierId, purchaseDate?, remarks?, items:[{ inventoryItemId, quantity(>0), unitCost?(null = item cost), batchNumber?, manufactureDate?, expiryDate? }] }` -> 201 data `{ id, number, totalAmount }`. Created as `Draft`; tax from item taxPercent.
- `POST /{id}/approve` purchase.approve — no body; Draft only -> data = purchase detail (status `Approved`)
- `POST /{id}/receive` purchase.receive — body optional `{ receivedDate? }`; Approved only; creates batches, raises stock, writes ledger -> data = purchase detail (status `Received`)
- `POST /{id}/cancel` purchase.approve OR purchase.create — `{ reason }`; Draft/Approved with nothing received -> detail (status `Cancelled`)

## Consumption `/api/inventory/consumption`
- `GET` inventory.view — q: `itemId, batchId, from, to, expiredOverride(bool)`; sort: id,consumptionDate,itemName,quantity
  row `{ id, inventoryItemId, itemCode, itemName, unitName, inventoryBatchId, batchNumber, stockTransactionId, quantity, unitCost, costValue, consumptionDate, purpose, branchId, consumedBy, consumedByName, expiredOverride, overrideReason, createdDate }`
- `POST` inventory.create — `{ inventoryItemId, inventoryBatchId?, quantity(>0), consumptionDate?, purpose?, expiredOverride?(false) }` -> 201 data `{ id, quantity, batchesUsed, currentStock }`.
  No batch = FEFO across batches (expired batches skipped unless override). `expiredOverride:true` needs permission `inventory.adjust` (else 422), a `purpose` (stored as override reason) and system setting inventory.allowExpiredOverride=true. Stock never goes negative (422 "Insufficient stock").

## Adjustments `/api/inventory/adjustments`
- `GET` inventory.view — ledger rows filtered to `transactionType=Adjustment`; q: `itemId, batchId, from, to`; same row/sort as stock-transactions
- `POST` inventory.adjust — `{ inventoryItemId, inventoryBatchId?, quantityDelta(signed, non-zero), reason(required) }` -> 201 data `{ id, previousStock, currentStock }`. Would-be-negative stock -> 422. Audited (StockAdjustment) by the procedure.

## Stock ledger `GET /api/inventory/stock-transactions` (inventory.view)
q: `itemId, batchId, type, from, to`; sort: id,transactionDate,itemName,transactionType,quantity (default newest first)
row `{ id, inventoryItemId, itemCode, itemName, unitName, inventoryBatchId, batchNumber, transactionType, quantity, unitCost, balanceAfter, referenceType, referenceId, remarks, transactionDate, createdBy, createdByName }`

## Alerts and summary (inventory.view)
- `GET /api/inventory/alerts/low-stock` -> data `[{ id(itemId), itemCode, itemName, categoryName, unitName, currentStock, reorderLevel, maxStockLevel, shortfall, unitCost, stockStatus(OutOfStock|Low) }]`
- `GET /api/inventory/alerts/expiring?days=` (default = setting inventory.expiryAlertDays) -> data `[{ id(batchId), inventoryItemId, itemCode, itemName, batchNumber, expiryDate, quantityAvailable, unitName, unitCost, stockValue, daysToExpiry(negative = expired), isExpired, status }]`
- `GET /api/inventory/summary` -> data `{ totalItems, activeItems, categoryCount, supplierCount, stockValue, lowStockCount, outOfStockCount, expiringBatchCount, expiredBatchCount, expiredStockValue, openPurchaseCount(Draft+Approved), pendingApprovalCount(Draft) }`

- `GET /{id}` expense.view
- `POST` expense.approve — `{ code(<=30), name(<=100), description? }` (code/name unique)

## Expenses `/api/expenses`
- `GET` expense.view — q: `from, to`(expense date), `categoryId, status, paymentModeId, branchId`; sort: id,expenseNumber,expenseDate,categoryName,amount,status,createdDate
  row `{ id, expenseNumber, expenseCategoryId, categoryName, expenseDate, amount, paymentModeId, paymentModeName, description, payee, receiptNo, branchId, branchName, collectionCenterId, status, approvedBy, approvedByName, approvedDate, rejectionReason, referenceType, referenceId, createdBy, createdByName, createdDate }`
- `GET /{id}` expense.view
- `POST` expense.create — `{ expenseCategoryId, expenseDate?(not future), amount(>0), paymentModeId?, description?, branchId?, payee?, receiptNo? }` -> 201 data `{ id, number, status }`. Status `Pending`, or `Approved` immediately when amount <= setting expense.autoApproveBelow (cash-out entry posted on approval).
- `POST /{id}/approve` expense.approve — body optional `{ remarks? }`; Pending only; posts cash-out entry -> data = expense
- `POST /{id}/reject` expense.approve — `{ reason }` required; Pending only -> data = expense

## Cash `/api/cash-transactions` (cash.view)
- `GET` — q: `from, to, type(In|Out), category, paymentModeId`; sort: id,transactionDate,transactionType,category,amount,balanceAfter (default newest first)
  row `{ id, transactionDate, transactionType, category, amount, balanceAfter, paymentModeId, paymentModeName, branchId, branchName, referenceType(Expense|CustomerPayment|FarmerPayment|Purchase|Salary|Manual), referenceId, remarks, createdBy, createdByName }`
- `GET /summary?from&to` -> data `{ from, to, openingBalance, totalIn, totalOut, netChange, closingBalance, transactionCount, byCategory:[{ category, totalIn, totalOut }] }` (no params = all time; opening = balance before `from`)

## Equipment `/api/maintenance/equipment`
- `GET` maintenance.view — q: `status, category, branchId, collectionCenterId, isActive`; sort: id,equipmentCode,name,category,status,purchaseDate,warrantyExpiry,nextDueDate,isActive
  row `{ id, equipmentCode, name, category, make, model, serialNumber, purchaseDate, purchaseCost, location, branchId, branchName, collectionCenterId, collectionCenterName, warrantyExpiry, vendorName, status, remarks, isActive, createdDate, nextDueDate, lastMaintenanceDate }`
- `GET /{id}` maintenance.view
- `POST` maintenance.create — `{ equipmentCode(<=30, unique), name, category?, make?, model?, serialNumber?, purchaseDate?, purchaseCost, location?, branchId?, collectionCenterId?, warrantyExpiry?, vendorName?, remarks? }` (status starts `Operational`)
- `PUT /{id}` maintenance.update — same + `status?`, `isActive?`

## Schedules `/api/maintenance/schedules`
- `GET` maintenance.view — q: `equipmentId, status, dueOnly(bool), assignedEmployeeId`; sort: id,equipmentName,taskName,nextDueDate,lastServiceDate,frequencyDays,status (default next due ascending). Deactivated (isActive=false) schedules are hidden.
  row `{ id, equipmentId, equipmentCode, equipmentName, taskName, description, frequencyDays, lastServiceDate, nextDueDate, alertBeforeDays, assignedEmployeeId, assignedEmployeeName, status, isActive, daysToDue, isOverdue, isDue }`
  `dueOnly=true`: Active schedules on non-retired equipment with nextDueDate <= today + alertBeforeDays.
- `GET /{id}` maintenance.view
- `POST` maintenance.create — `{ equipmentId, taskName, description?, frequencyDays(1-3650, default 30), lastServiceDate?, nextDueDate?(default (lastServiceDate or today)+frequencyDays), alertBeforeDays(0-365, default 7), assignedEmployeeId? }`
- `PUT /{id}` maintenance.update — `{ taskName, description?, frequencyDays, lastServiceDate?, nextDueDate?(null = keep), alertBeforeDays, assignedEmployeeId?, status?(Active|Paused), isActive? }` (equipment cannot change)

## Records `/api/maintenance/records` and due list
- `GET /api/maintenance/records` maintenance.view — q: `equipmentId, scheduleId, from, to, type`; sort: id,maintenanceDate,equipmentName,maintenanceType,cost,nextDueDate
  row `{ id, equipmentId, equipmentCode, equipmentName, maintenanceScheduleId, taskName, maintenanceType, maintenanceDate, description, vendorName, cost, nextDueDate, performedBy, downtimeHours, invoiceNo, status, remarks, createdBy, createdByName, createdDate }`
- `GET /api/maintenance/records/{id}` maintenance.view
- `POST /api/maintenance/records` maintenance.create — `{ equipmentId, maintenanceScheduleId?, maintenanceDate?(not future), description(required), vendorName?, cost(>=0), maintenanceType?, performedBy?, downtimeHours?, invoiceNo?, remarks? }` -> 201 data `{ id, nextDueDate, expenseId }`.
  With a schedule: type Preventive, schedule lastServiceDate/nextDueDate advance (+frequencyDays). Without: Corrective. Equipment `UnderMaintenance` returns to `Operational`. cost>0 raises a Pending expense (setting maintenance.createExpense, category "Maintenance"), `expenseId` is null if none.
- `GET /api/maintenance/due?days=` maintenance.view — data `[{ id(scheduleId), equipmentId, equipmentCode, equipmentName, location, taskName, frequencyDays, lastServiceDate, nextDueDate, daysToDue, isOverdue, assignedEmployeeId, assignedEmployeeName }]` (no `days` = each schedule's own alertBeforeDays; includes overdue)
