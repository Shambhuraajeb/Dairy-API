# B1 API: Lookups, Farmers, Animals, Dashboard

Envelope, errors and auth as in `foundation.md`. All routes need `Authorization: Bearer <token>`.
Lists: `GET ...?page&pageSize&search&sortBy&sortDir&<filters>` -> `data = { items, total, page, pageSize, totalPages }` (`PagedResult<T>`).
Dates in requests: `"2026-10-05"` (or ISO datetime). Dates in responses: ISO datetime strings (`"2026-10-05T00:00:00"`); take the first 10 chars for date-only fields.
`Farmer` role: farmers/animals/loans/advances are restricted to the caller's own farmer (other ids -> 404). Perm column: `a|b` = any of.
Stored-procedure/business-rule failures come back as 422 with the message; duplicates as 409.

## 2. Farmers `/api/farmers`
Status model: `verificationStatus` Pending -> Verified (or Rejected); `status` Pending -> Active -> Inactive (Blocked reserved). Activation needs `verificationStatus=Verified`, a collection center, and >= 1 active bank account.

Farmer list item (`FarmerListDto`): `{ id, farmerCode, fullName, fatherName, mobile, email, milkType, collectionCenterId, collectionCenterName, branchId, joinDate, verificationStatus, status, isActive, animalCount }`
Farmer detail (`FarmerDetailDto`) = list item + `{ branchName, alternateMobile, gender, dateOfBirth, aadhaarNo, panNo, verifiedBy, verifiedDate, verificationRemarks, statusReason, activatedDate, deactivatedDate, notes, createdDate, addresses: [Address], bankAccounts: [BankAccount], documents: [Document] }`
Address: `{ id, farmerId, addressType, line1, line2, village, taluka, district, city, state, pincode, latitude, longitude, isDefault }`
BankAccount: `{ id, farmerId, accountHolderName, bankName, branchName, accountNumber, ifscCode, upiId, isPrimary }`
Document: `{ id, farmerId, documentTypeId, documentTypeName, documentNumber, fileName, hasFile, contentType, fileSize, expiryDate, verificationStatus, verifiedDate, remarks, createdDate }`

| Method URL | Perm | Query / body | Data |
|---|---|---|---|
| GET `/api/farmers` | farmer.view | `status, verificationStatus, collectionCenterId, milkType, search, sortBy(id\|farmerCode\|fullName\|mobile\|milkType\|joinDate\|status\|verificationStatus\|collectionCenterName\|createdDate)` | Paged FarmerListDto |
| GET `/api/farmers/{id}` | farmer.view | | FarmerDetailDto |
| POST `/api/farmers` | farmer.create | body below | 201 FarmerDetailDto |
| PUT `/api/farmers/{id}` | farmer.update | `{ fullName, fatherName, mobile, alternateMobile, email, gender, dateOfBirth, aadhaarNo, panNo, collectionCenterId, branchId, milkType, joinDate, notes }` | FarmerDetailDto |
| POST `/api/farmers/{id}/verify` | farmer.update | optional `{ approved: true, remarks }` (approved=false rejects, remarks required then) | FarmerDetailDto |
| POST `/api/farmers/{id}/activate` | farmer.update | no body | FarmerDetailDto (422 if not verified / no center / no bank account) |
| POST `/api/farmers/{id}/deactivate` | farmer.update | `{ reason }` (required) | FarmerDetailDto |
| GET `/api/farmers/{id}/summary` | farmer.view | | `{ farmerId, animalCount, milkingAnimalCount, collectionsThisMonth, quantityThisMonth, amountThisMonth, pendingApprovalCount, payableAmount, loanBalance, advanceBalance, lastCollectionDate }` |

Create body: `{ farmerCode?, fullName*, fatherName, mobile*, alternateMobile, email, gender(Male|Female|Other), dateOfBirth, aadhaarNo(12 digits), panNo, collectionCenterId, branchId, milkType*(Cow|Buffalo|Mixed), joinDate, notes, address?: AddressBody, bankAccount?: BankBody }`. Blank `farmerCode` -> `FRM-000001`-style auto code. Mobile = 10-13 digits (optional +). New farmers start `Pending/Pending`.
AddressBody: `{ addressType(Home|Farm|Billing), line1*, line2, village, taluka, district, city, state, pincode(6 digits), latitude, longitude, isDefault }`
BankBody: `{ accountHolderName*, bankName*, branchName, accountNumber*, ifscCode*(ABCD0123456), upiId, isPrimary }` (first address/account is automatically default/primary)

Detail-tab lists (all paged; `Farmer` role: own id only):
| GET `/api/farmers/{id}/animals` | farmer.view\|animal.view | AnimalQuery filters (breedId, status, animalType, ...) | Paged AnimalListDto (section 3) |
| GET `/api/farmers/{id}/collections` | farmer.view\|collection.view | `dateFrom, dateTo, status, search(collection no), sortBy(collectionDate\|collectionNumber\|quantityLiters\|amount\|status)` | Paged `{ id, collectionNumber, collectionDate, shiftName, collectionCenterName, quantityLiters, fat, snf, rate, amount, status, settlementStatus }` |
| GET `/api/farmers/{id}/payments` | farmer.view\|payment.view | `dateFrom, dateTo, status, search, sortBy(paymentDate\|paymentNumber\|netPayable\|status)` | Paged `{ id, paymentNumber, paymentDate, periodFrom, periodTo, totalQuantity, grossAmount, deductionAmount, netPayable, paidAmount, balanceAmount, status, paidDate }` |
| GET `/api/farmers/{id}/loans` | farmer.view\|loan.view | `status, search` | Paged FarmerLoanListDto (section 2.2) |

Sub-resources (perm: GET `farmer.view`; POST/PUT/DELETE `farmer.update`):
- `GET /api/farmers/{id}/addresses` -> `[Address]`; `POST` (AddressBody) -> 201 Address; `PUT /api/farmers/{id}/addresses/{addressId}` (AddressBody) -> Address; `DELETE .../addresses/{addressId}` -> message.
- `GET /api/farmers/{id}/bank-accounts` -> `[BankAccount]`; `POST` (BankBody) -> 201 BankAccount (409 if the account number already exists for the farmer); `PUT .../bank-accounts/{bankAccountId}` (BankBody); `DELETE .../bank-accounts/{bankAccountId}` (422 if it is the last account of an Active farmer).
- `GET /api/farmers/{id}/documents` -> `[Document]`.
- `POST /api/farmers/{id}/documents` multipart/form-data -> 201 Document. Fields: `file` (optional; pdf/jpg/jpeg/png, <= 10 MB), `documentTypeId`, `documentNumber`, `fileName` (required when no file), `expiryDate`, `remarks`.
- `PUT /api/farmers/{id}/documents/{documentId}` `{ documentTypeId, documentNumber, expiryDate, remarks, verificationStatus?(Pending|Verified|Rejected) }` -> Document.
- `DELETE /api/farmers/{id}/documents/{documentId}` -> message. `GET /api/farmers/{id}/documents/{documentId}/download` (farmer.view) -> file stream (use authenticated fetch/blob; not JSON).

### 2.1 Advances `/api/farmer-advances`
Advance: `{ id, advanceNumber, farmerId, farmerCode, farmerName, advanceDate, amount, recoveredAmount, balanceAmount, recoveryPerSettlement, purpose, paymentModeId, paymentModeName, referenceNo, status(Open|Recovered|Cancelled), approvedDate, remarks, createdDate }`
- `GET /api/farmer-advances` (loan.view) `farmerId, status, dateFrom, dateTo, search, sortBy(advanceNumber|advanceDate|farmerName|amount|balanceAmount|status)` -> Paged Advance.
- `GET /api/farmer-advances/{id}` (loan.view) -> Advance.
- `POST /api/farmer-advances` (loan.create) `{ farmerId*, advanceDate, amount*, recoveryPerSettlement, purpose, paymentModeId, referenceNo, remarks }` -> 201 Advance (farmer must be Active; created Open and approved).

### 2.2 Loans `/api/farmer-loans`
LoanListDto: `{ id, loanNumber, farmerId, farmerCode, farmerName, loanDate, principalAmount, interestRate, interestAmount, totalPayable, numberOfInstallments, installmentAmount, firstInstallmentDate, paidAmount, outstandingAmount, status(Active|Closed|Cancelled), purpose, paidInstallments, nextDueDate }`
LoanDto = LoanListDto + `{ interestType, paymentModeId, paymentModeName, referenceNo, approvedDate, closedDate, remarks, createdDate, installments: [{ id, farmerLoanId, installmentNo, dueDate, amount, principalComponent, interestComponent, paidAmount, balanceAmount, paidDate, status(Pending|Partial|Paid), isOverdue, paymentSource, farmerPaymentId, remarks }] }`
- `GET /api/farmer-loans` (loan.view) `farmerId, status, search, sortBy(loanNumber|loanDate|farmerName|principalAmount|outstandingAmount|status)` -> Paged LoanListDto.
- `GET /api/farmer-loans/{id}` (loan.view) -> LoanDto.
- `POST /api/farmer-loans` (loan.create) `{ farmerId*, principalAmount*, interestRate*(0-100 annual %), numberOfInstallments*(1-120), startDate*(first due date), remarks }` -> 201 LoanDto (via `sp_CreateFarmerLoan`; farmer must be Active).
- `POST /api/farmer-loans/{id}/installments/{no}/pay` (loan.update) optional `{ amount }` (omit = pay the remaining balance; cannot exceed it) -> LoanDto (via `sp_PayLoanInstallment`).

## 3. Animals
Animal list item (`AnimalListDto`): `{ id, tagNumber, name, farmerId, farmerCode, farmerName, breedId, breedName, animalType(Cow|Buffalo|Goat), gender(Female|Male), dateOfBirth, ageMonths, milkingStatus(Milking|Dry|Heifer|Calf|NotApplicable), pregnancyStatus(NotPregnant|Pregnant|Unknown), expectedDeliveryDate, status(Active|Sick|Sold|Dead|Archived), registrationDate, isActive }`
Animal detail = list item + `{ color, weightKg, source(Born|Purchased), lactationNo, lastCalvingDate, statusDate, remarks, createdDate, sale: Sale|null, death: Death|null }`
Sale: `{ id, animalId, saleDate, buyerName, buyerMobile, buyerAddress, salePrice, paymentModeId, referenceNo, reason, remarks }`; Death: `{ id, animalId, deathDate, cause, causeCategory(Disease|Accident|Age|Calving|Unknown), vetName, postMortemDone, lossAmount, remarks }`

| Method URL | Perm | Query / body | Data |
|---|---|---|---|
| GET `/api/animals` | animal.view | `farmerId, breedId, status, animalType, milkingStatus, pregnancyStatus, search(tag/name/farmer), sortBy(tagNumber\|name\|farmerName\|breedName\|animalType\|gender\|milkingStatus\|pregnancyStatus\|status\|registrationDate\|dateOfBirth)` | Paged AnimalListDto |
| GET `/api/animals/due` | animal.view | `type*=vaccination\|deworming\|pregnancy, days=30, farmerId, search, sortBy(dueDate\|tagNumber\|farmerName\|title)` | Paged `{ animalId, tagNumber, animalName, farmerId, farmerName, dueType, title, dueDate, daysRemaining(negative=overdue), status, refId }` (Active/Sick animals only) |
| GET `/api/animals/{id}` | animal.view | | AnimalDetailDto |
| POST `/api/animals` | animal.create | `{ tagNumber*, farmerId*, breedId, name, animalType*, gender*, dateOfBirth, color, weightKg, source*, registrationDate, lactationNo, lastCalvingDate, milkingStatus*, pregnancyStatus*, expectedDeliveryDate(required if Pregnant), remarks }` | 201 AnimalDetailDto (farmer must be Active; tag unique -> 409) |
| PUT `/api/animals/{id}` | animal.update | same body as create (farmerId may reassign to another Active farmer) | AnimalDetailDto (422 once Sold/Dead/Archived) |
| POST `/api/animals/{id}/sale` | animal.update | `{ saleDate, buyerName*, buyerMobile, buyerAddress, salePrice*, paymentModeId, referenceNo, reason, remarks }` | AnimalDetailDto (status Sold) |
| POST `/api/animals/{id}/death` | animal.update | `{ deathDate, cause, causeCategory*, vetName, postMortemDone, lossAmount, remarks }` | AnimalDetailDto (status Dead) |
| POST `/api/animals/{id}/archive` | animal.update | optional `{ reason }` | AnimalDetailDto (status Archived) |
| GET `/api/animals/{id}/lifecycle` | animal.view | | `[{ eventDate, eventType(Registration\|Health\|Vaccination\|Deworming\|Breeding\|Pregnancy\|Delivery\|Sale\|Death\|Archive), title, details, refId }]` newest first |

Only Active/Sick animals can be edited, sold, killed or archived; new records are blocked on Sold/Dead/Archived animals (422).
Animal `status` becomes `Sick` while a health record is Open/Ongoing and returns to `Active` when all are Recovered. `pregnancyStatus`/`expectedDeliveryDate` follow pregnancy records; a pregnancy saved as `Delivered` increments `lactationNo`, sets `lastCalvingDate` and `milkingStatus=Milking`.

### 3.1 Per-animal records `/api/animals/{animalId}/...`
For each resource: `GET` (animal.view; paged; `dateFrom, dateTo, sortBy=date|id, sortDir`), `POST` (animal.create|animal.update; 201), `PUT /{id}` (animal.update), `DELETE /{id}` (animal.update; health/vaccination/deworming/breeding/pregnancy are soft-deleted, milk-production is removed). Response row = body fields + `id, animalId`. Breeding, pregnancy and milk-production apply to female animals only.

| Path | Body / row fields |
|---|---|
| `health` | `recordDate*, healthCondition*, symptoms, diagnosis, treatment, medicines, severity(Mild\|Moderate\|Severe), vetName, vetEmployeeId, cost, status(Open\|Ongoing\|Recovered), followUpDate, recoveredDate(required if Recovered), remarks` |
| `vaccinations` | `vaccineName*, vaccinationDate*, nextDueDate, doseNumber, batchNumber, administeredBy, vetEmployeeId, cost, status(Completed\|Scheduled\|Missed), remarks` |
| `dewormings` | `dewormingDate*, medicineName*, dosage, nextDueDate, administeredBy, cost, status(Completed\|Scheduled\|Missed), remarks` |
| `breedings` | `breedingDate*, breedingMethod(NaturalService\|ArtificialInsemination), bullName, semenCode, technicianName, heatDate, expectedDeliveryDate, result(Pending\|Successful\|Failed), confirmedDate, cost, remarks` |
| `pregnancies` | `breedingRecordId, confirmedDate*, expectedDeliveryDate*, actualDeliveryDate(required if Delivered), status(Pregnant\|Delivered\|Aborted), deliveryOutcome(LiveBirth\|Stillbirth\|Abortion), calfCount, calfAnimalId, calfGender, lastCheckupDate, remarks` |
| `milk-production` | `productionDate*, shiftName(Morning\|Evening), quantityLiters*(>0), fat, snf, remarks` (unique per animal/date/shift -> 409) |

### 3.2 Breeds `/api/breeds`
Breed: `{ id, code, name, animalType, averageDailyYield, description, isActive }`
- `GET /api/breeds` (animal.view) `animalType, isActive, search, sortBy(code|name|animalType|averageDailyYield|isActive)` -> Paged Breed. `GET /api/breeds/{id}` (animal.view).
- `POST /api/breeds` (animal.create) `{ code*, name*, animalType*, averageDailyYield, description }` -> 201 Breed (code or name duplicate -> 409).
- `PUT /api/breeds/{id}` (animal.update) same body + `isActive?` (false deactivates) -> Breed. `DELETE /api/breeds/{id}` (animal.update) -> Breed (deactivated).

## 4. Dashboard `/api/dashboard/*` (dashboard.view)
- `GET /api/dashboard/summary?branchId&collectionCenterId` -> flat `{ milkCollectedToday, morningCollection, eveningCollection, avgFat, avgSnf, todayMilkValue, salesToday, salesThisMonth, farmerOutstanding, customerOutstanding, activeSubscriptions, lowStockCount, expiringInventoryCount, sickAnimals, vaccinationsDue, maintenanceDue, deliverySuccessRate, revenue, expenses, profit }` (numbers).
- `GET /api/dashboard/charts?days=30` (1..365) -> `{ milkCollectionTrend, salesTrend, collectionByCenter, topFarmers, productSales, expenseCategories }`, each `[{ label, value }]` (trend labels are `yyyy-MM-dd`).
- `GET /api/dashboard/collection?collectionCenterId` -> `{ collectionDate, shiftId, shiftName, startTime("06:00:00"), endTime, isCurrentShift, farmersServed, totalCollections, totalLiters, acceptedLiters, rejectedLiters, avgFat, avgSnf, acceptedCount, rejectedCount, totalAmount, pendingApprovals }` (current shift, else the most recent one; today only).
- `GET /api/dashboard/inventory` -> `{ summary: { stockValue, totalItems, lowStockCount, outOfStockCount, expiringBatchCount, expiredBatchCount }, lowStockItems: [{ id, itemCode, name, currentStock, reorderLevel, unitCost, unitCode, unitSymbol }], expiringBatches: [{ id, inventoryItemId, itemCode, itemName, batchNumber, expiryDate, quantityAvailable, daysToExpiry }], recentPurchases: [{ id, purchaseNumber, supplierName, purchaseDate, totalAmount, status, paymentStatus }], consumptionTrend: [{ label, value }] }`
- `GET /api/dashboard/customer?customerId` -> `{ customerId, subscriptions: [{ id, subscriptionNumber, planName, productName, quantity, unitPrice, frequency, deliverySlot, status, startDate, endDate, nextOrderDate, addressLine }], todayDeliveries: [{ id, orderNumber, deliverySlot, orderStatus, totalAmount, deliveryId, deliveryNumber, deliveryStatus, deliveredDate }], currentBill: { id, invoiceNumber, invoiceDate, dueDate, periodFrom, periodTo, totalAmount, paidAmount, balanceAmount, status } | null, outstanding: { id, outstandingBalance, creditLimit, overdueAmount, unbilledAmount, monthToDateOrders } | null, recentDeliveries: [{ id, deliveryNumber, orderNumber, deliveryDate, deliverySlot, status, deliveredDate, failureReason, totalAmount }], openComplaints: [{ id, complaintNumber, subject, category, priority, status, createdDate }] }`. Customer/Distributor roles always get their own data (query ignored); staff need `customer.view` and `?customerId=` (400 if missing).
