# B4 API: customers, subscriptions, complaints, products, orders, delivery, billing

Conventions: see `foundation.md`. All responses `{success,message,data,errors}`; lists = `data: PagedResult<T> {items,total,page,pageSize,totalPages}` from `?page&pageSize&search&sortBy&sortDir(asc|desc)` plus the filters below.
Dates in requests: `yyyy-MM-dd` (ISO datetime also accepted). Dates in responses: ISO datetime (`2026-10-05T00:00:00`); slice the first 10 chars for date-only fields. Ids are numbers. Numeric money/qty are JSON numbers.
Errors: validation 400 (`errors[{field,message}]`), unknown/not-owned id 404, duplicate code 409, business-rule/stored-procedure message 422, ownership 403.
"Own only" = roles `Customer` / `Distributor / B2B Customer` are forced to their own `customerId` (list filters are overridden, single records of others return 404).
"Soft delete" = `DELETE` deactivates (`isActive=false`), never removes rows. Master `PUT` bodies accept `isActive` (null = unchanged).

## Enums (exact strings)
- Customer.customerType / price customerType: `Retail | Distributor`; Customer.status: `Active | Inactive | Blocked`
- Address.addressType: `Home | Office | Shop | Billing | Delivery`
- Slot (deliverySlot / slot): `Morning | Evening`
- Plan.frequency / Subscription.frequency: `Daily | Alternate | Weekly` (weekly `daysOfWeek` = comma list `Mon,Thu`); plan.billingCycle: `Daily | Weekly | Monthly`
- Subscription.status: `Active | Paused | Cancelled | Expired`; Pause.status: `Active | Resumed | Completed | Cancelled`
- Complaint.category: `Quality | Delivery | Billing | Service | Other`; priority: `Low | Medium | High | Urgent`; status: `Open | Assigned | InProgress | Resolved | Closed`
- Order.status: `Pending | Confirmed | Scheduled | Dispatched | Delivered | Cancelled | Failed`; order.source: `Manual | Subscription`; order.paymentStatus: `Unpaid | PartiallyPaid | Paid`
- Vehicle.vehicleType: `Van | Truck | Tanker | Bike | Auto`; vehicle.status: `Available | OnRoute | Maintenance | Inactive`
- Schedule.status: `Planned | Dispatched | Completed`
- Delivery.status: `Pending | Dispatched | Delivered | Failed | Cancelled`; confirmation.outcome: `Delivered | Partial | Failed`
- Invoice.status: `Draft | Issued | PartiallyPaid | Paid | Cancelled` (filter also accepts `Overdue`); invoice.invoiceType: `Order | Consolidated`
- Payment.status: `Received | Cancelled`

## Customers `/api/customers`

CustomerDto = `{id, customerCode, customerType, name, contactPerson, mobile, alternateMobile, email, gstNumber, branchId, branchName, creditLimit, creditDays, discountPercent, outstandingBalance, joinDate, status, notes, isActive, createdDate, activeSubscriptions}`

| Method URL | Permission | Notes |
|---|---|---|
| `GET /api/customers` | customer.view | query `type, status, isActive, search`(name/code/mobile/email/contact); sortBy `id,customerCode,name,customerType,mobile,status,outstandingBalance,joinDate,createdDate`; default name asc. Own only. data `PagedResult<CustomerDto>` |
| `GET /api/customers/{id}` | customer.view | own only. data `CustomerDto` |
| `POST /api/customers` | customer.create | 201 `CustomerDto` |
| `PUT /api/customers/{id}` | customer.update | `CustomerDto` |
| `POST /api/customers/{id}/activate` | customer.update | sets status Active, isActive true. `CustomerDto` |
| `POST /api/customers/{id}/deactivate` | customer.update | sets status Inactive, isActive false. `CustomerDto` |
| `GET /api/customers/{id}/summary` | customer.view | own only. data below |

Create body: `{customerCode?(auto CUS0001..), customerType:"Retail", name*, contactPerson?, mobile*(10-13 digits, optional +), alternateMobile?, email?, gstNumber?, branchId?, creditLimit:0, creditDays:0, discountPercent:0, joinDate?(default today), notes?}`
Update body: same without `customerCode`.
Summary data: `{id, customer:CustomerDto, activeSubscriptions, pausedSubscriptions, totalOrders, pendingOrders, deliveredOrders, lastOrderDate, totalInvoiced, openInvoices, outstandingAmount, overdueAmount, unallocatedCredit, lastPaymentDate, lastPaymentAmount, openComplaints}`

### Addresses
AddressDto = `{id, customerId, addressType, contactName, contactMobile, line1, line2, landmark, city, state, pincode, latitude, longitude, routeId, routeName, deliveryInstructions, isDefault, isActive}`
- `GET /api/customers/{id}/addresses` (customer.view, own only) -> `AddressDto[]` (active only, default first, not paged)
- `POST /api/customers/{id}/addresses` (customer.create OR customer.update) -> 201 `AddressDto`
- `PUT /api/customers/{id}/addresses/{addressId}` (customer.update) -> `AddressDto`
- `DELETE /api/customers/{id}/addresses/{addressId}` (customer.update) -> data null (soft delete; 422 if an active/paused subscription uses it)
- Body (POST/PUT): `{addressType:"Home", contactName?, contactMobile?, line1*, line2?, landmark?, city?, state?, pincode?(6 digits), latitude?, longitude?, routeId?, deliveryInstructions?, isDefault:false}`. First address becomes default; `isDefault:true` unsets the others.

### Convenience lists (paged, `customerId` forced to `{id}`; own only)
- `GET /api/customers/{id}/orders` (order.view) = `/api/orders` filters
- `GET /api/customers/{id}/invoices` (invoice.view) = `/api/invoices` filters
- `GET /api/customers/{id}/payments` (custpayment.view) = `/api/payments` filters
- `GET /api/customers/{id}/subscriptions` (subscription.view) = `/api/subscriptions` filters
- `GET /api/customers/{id}/complaints` (complaint.view) = `/api/customer-complaints` filters

## Complaints `/api/customer-complaints`

ComplaintDto = `{id, complaintNumber, customerId, customerName, customerCode, salesOrderId, orderNumber, deliveryId, deliveryNumber, category, subject, description, priority, status, assignedTo(userId), assignedToName, assignedDate, resolution, resolvedBy, resolvedDate, closedBy, closedDate, feedbackRating, feedbackComments, feedbackDate, createdDate}`

- `GET /api/customer-complaints` (complaint.view; own only) query `customerId, status, category, priority, assignedTo, from, to`(created date), `search`; sortBy `id,complaintNumber,customerName,category,priority,status,createdDate`; default createdDate desc.
- `GET /api/customer-complaints/{id}` (complaint.view; own only)
- `POST /api/customer-complaints` (complaint.create) body `{customerId?(required for staff, ignored for customers), salesOrderId?, deliveryId?, category:"Other", subject*, description*, priority:"Medium"}` -> 201 `ComplaintDto` (number `CMPyymmNNNNNN`)
- `POST /api/customer-complaints/{id}/assign` (complaint.update) `{assignedTo*:userId}` -> `ComplaintDto` (Open becomes Assigned; assignee gets a Notification)
- `POST /api/customer-complaints/{id}/status` (complaint.update) `{status*:"Open|Assigned|InProgress", assignedTo?}` -> `ComplaintDto` (Resolved/Closed via the actions below; also reopens a Resolved one)
- `POST /api/customer-complaints/{id}/resolve` (complaint.update) `{resolution*}` -> `ComplaintDto`
- `POST /api/customer-complaints/{id}/close` (complaint.update) no body; only from Resolved -> `ComplaintDto`
- `POST /api/customer-complaints/{id}/feedback` (complaint.view; Customer roles only, own complaint, Resolved/Closed, once) `{rating*:1-5, comments?}` -> `ComplaintDto`

## Subscription plans `/api/subscription-plans`

PlanDto = `{id, planCode, name, description, frequency, daysOfWeek, productId, productName, defaultQuantity, pricePerUnit, discountPercent, billingCycle, minimumDays, isActive, activeSubscriptions}`

- `GET /api/subscription-plans` (subscription.view) query `frequency, productId, isActive, search`; sortBy `id,planCode,name,frequency,defaultQuantity,isActive`; default name.
- `GET /api/subscription-plans/{id}` (subscription.view)
- `POST /api/subscription-plans` (subscription.create) `{planCode?(auto PLN0001..), name*, description?, frequency:"Daily", daysOfWeek?, productId?, defaultQuantity*(>0), pricePerUnit?(null = price list), discountPercent:0, billingCycle:"Monthly", minimumDays:0}` -> 201 `PlanDto`
- `PUT /api/subscription-plans/{id}` (subscription.update) same body without planCode, plus `isActive?` -> `PlanDto`
- `DELETE /api/subscription-plans/{id}` (subscription.update) soft delete; 422 while active subscriptions use the plan

## Subscriptions `/api/subscriptions`

SubscriptionDto = `{id, subscriptionNumber, customerId, customerName, customerCode, subscriptionPlanId, planName, customerAddressId, addressText, productId, productName, quantity, unitPrice, frequency, daysOfWeek, startDate, endDate, deliverySlot, status, nextOrderDate, lastOrderDate, cancelledDate, cancelReason, remarks, createdDate}`
SubscriptionDetailDto = SubscriptionDto + `pauses:[{id, customerSubscriptionId, pauseFrom, pauseTo, reason, resumedDate, resumedBy, status}]`

- `GET /api/subscriptions` (subscription.view; own only) query `customerId, status, productId, slot, search`; sortBy `id,subscriptionNumber,customerName,productName,status,startDate,nextOrderDate,createdDate`; default id desc. -> `PagedResult<SubscriptionDto>`
- `GET /api/subscriptions/{id}` (subscription.view; own only) -> `SubscriptionDetailDto`
- `POST /api/subscriptions` (subscription.create; sp_CreateCustomerSubscription) `{customerId*, subscriptionPlanId*, customerAddressId*, productId?(plan product), quantity?(plan default), startDate?(today), endDate?, deliverySlot:"Morning"}` -> 201 `SubscriptionDetailDto` (unit price = plan price or price list, less plan discount)
- `PUT /api/subscriptions/{id}` (subscription.update; Active/Paused only; own for customers) `{quantity?, endDate?(always applied; null = open ended), deliverySlot?, customerAddressId?, remarks?}` -> `SubscriptionDetailDto`
- `POST /api/subscriptions/{id}/pause` (subscription.update; customers own) body optional `{pauseFrom?(today), pauseTo?(until resumed), reason?}` -> `SubscriptionDetailDto`
- `POST /api/subscriptions/{id}/resume` (subscription.update; customers own) no body -> `SubscriptionDetailDto`
- `POST /api/subscriptions/{id}/cancel` (subscription.update; NOT allowed for customer roles) body optional `{reason?}` -> `SubscriptionDetailDto`
- `POST /api/subscriptions/generate-orders` (subscription.update; sp_CreateSubscriptionOrders) body optional `{forDate?(today)}` -> data `{ordersCreated, forDate}`

## Products

- `GET /api/product-categories` (product.view) query `isActive, search`; sortBy `id,code,name,isActive`. Item `{id, code, name, description, isActive, productCount}`
- `GET /api/product-categories/{id}` (product.view)
- `POST /api/product-categories` (product.create) `{code?(auto PCAT001..), name*, description?}` -> 201
- `PUT /api/product-categories/{id}` (product.update) `{code*, name*, description?, isActive?}`
- `DELETE /api/product-categories/{id}` (product.update) soft delete; 422 while active products use it

ProductDto = `{id, productCode, name, productCategoryId, categoryName, unitId, unitCode, unitName, description, taxPercent, hsnCode, isMilkBased, milkLitersPerUnit, defaultPrice, currentPrice(Retail today), distributorPrice(today), currentStock, reorderLevel, shelfLifeDays, imagePath, isActive}`
- `GET /api/products` (product.view) query `categoryId, isActive, isMilkBased, lowStock(true = at/below reorder level), search`; sortBy `id,productCode,name,categoryName,defaultPrice,currentStock,isActive`
- `GET /api/products/{id}` (product.view)
- `GET /api/products/{id}/price?customerType=Retail&date=yyyy-MM-dd` (product.view) -> `{productId, customerType, date, price, source:"PriceList|Default", taxPercent}`
- `POST /api/products` (product.create) `{productCode?(auto PRD0001..), name*, productCategoryId*, unitId*, description?, taxPercent:0, hsnCode?, isMilkBased:false, milkLitersPerUnit?, defaultPrice:0, currentStock:0, reorderLevel:0, shelfLifeDays?}` -> 201
- `PUT /api/products/{id}` (product.update) same with `productCode*`, `currentStock?`(null = unchanged), `isActive?`
- `DELETE /api/products/{id}` (product.update) soft delete; 422 while open orders/active subscriptions use it
- Note: order stock check applies only to non-milk products with stock>0 or reorderLevel>0.

PriceDto = `{id, productId, productName, productCode, customerType, price, effectiveFrom, effectiveTo, isActive, createdDate}`
- `GET /api/product-prices` (product.view) query `productId, customerType, currentOnly, isActive, search`; sortBy `id,productName,customerType,price,effectiveFrom,effectiveTo`; default effectiveFrom desc
- `POST /api/product-prices` (product.update) `{productId*, customerType:"Retail", price*, effectiveFrom*, effectiveTo?}` -> 201 `PriceDto`. The currently open price of the same product/type is closed the day before `effectiveFrom`; 422 if another price already starts inside the new period.
- `DELETE /api/product-prices/{id}` (product.update) soft delete

## Orders `/api/orders`

OrderListDto = `{id, orderNumber, customerId, customerName, customerCode, customerAddressId, addressText, customerSubscriptionId, routeId, routeName, orderDate, deliveryDate, deliverySlot, source, subTotal, taxAmount, discountAmount, deliveryCharge, totalAmount, paidAmount, status, paymentStatus, invoiceId, invoiceNumber, totalQuantity, remarks, createdDate}`
OrderDetailDto = OrderListDto + `{confirmedDate, cancelledDate, cancelReason, lines:[{id, productId, productCode, productName, unitCode, quantity, deliveredQuantity, unitPrice, discountAmount, taxPercent, taxAmount, lineTotal, remarks}], delivery:{id, deliveryNumber, status, deliveryScheduleId, routeId, routeName, driverEmployeeId, driverName, assignedUserId, dispatchedDate, deliveredDate, failureReason} | null}`

- `GET /api/orders` (order.view; own only) query `customerId, status, from, to`(delivery date range), `slot, routeId, source, search`; sortBy `id,orderNumber,customerName,orderDate,deliveryDate,deliverySlot,totalAmount,status,createdDate`; default deliveryDate desc. -> `PagedResult<OrderListDto>`
- `GET /api/orders/{id}` (order.view; own only) -> `OrderDetailDto`
- `POST /api/orders` (order.create; sp_CreateSalesOrder) `{customerId?(required for staff; ignored for customers), customerAddressId?(default address), deliveryDate*(>= today), deliverySlot:"Morning", remarks?, items:[{productId*, quantity*(>0), unitPrice?(staff only; null = price list)}]}` -> 201 `OrderDetailDto`. Created as `Confirmed`; credit limit and stock are validated by the procedure (422).
- `PUT /api/orders/{id}` (order.update; Pending/Confirmed, not invoiced) `{customerAddressId?, deliveryDate?, deliverySlot?, remarks?(always applied)}` -> `OrderDetailDto`
- `POST /api/orders/{id}/cancel` (order.update OR order.create; customers: own and Pending/Confirmed only) body optional `{reason?}` -> `OrderDetailDto`. Staff may also cancel Scheduled/Failed (a Pending delivery is cancelled); 422 once Dispatched/Delivered/invoiced.

## Delivery

- `GET /api/routes/{id}` (route.view)
- `POST /api/routes` (route.manage) `{code?(auto RT004..), name*, branchId?, description?, startLocation?, endLocation?, distanceKm:0, estimatedMinutes:0, defaultVehicleId?, defaultDriverEmployeeId?}` -> 201
- `PUT /api/routes/{id}` (route.manage) same with `code*` + `isActive?`
- `DELETE /api/routes/{id}` (route.manage) soft delete; 422 while upcoming non-completed schedules exist

VehicleDto = `{id, registrationNo, vehicleType, make, model, capacity, capacityUnit, driverEmployeeId, driverName, branchId, fuelType, insuranceExpiry, fitnessExpiry, status, isActive}`
- `GET /api/vehicles` (route.view) query `status, vehicleType, isActive, search`; sortBy `id,registrationNo,vehicleType,capacity,status,insuranceExpiry,fitnessExpiry`
- `GET /api/vehicles/{id}` (route.view)
- `POST /api/vehicles` (route.manage) `{registrationNo*, vehicleType:"Van", make?, model?, capacity:0, capacityUnit:"Liters", driverEmployeeId?, branchId?, fuelType?, insuranceExpiry?, fitnessExpiry?, status:"Available"}` -> 201
- `PUT /api/vehicles/{id}` (route.manage) same + `isActive?`
- `DELETE /api/vehicles/{id}` (route.manage) soft delete (status Inactive); 422 while upcoming schedules use it

ScheduleDto = `{id, routeId, routeCode, routeName, vehicleId, vehicleNo, driverEmployeeId, driverName, scheduleDate, slot, status, plannedStartTime("HH:mm"|null), dispatchedDate, completedDate, remarks, deliveryCount, deliveredCount, isActive}`
- `GET /api/delivery-schedules` (route.view; drivers see only their own) query `date, from, to, routeId, status, slot, driverEmployeeId, search`; sortBy `id,scheduleDate,slot,routeName,status,driverName`; default scheduleDate desc
- `GET /api/delivery-schedules/{id}` (route.view)
- `POST /api/delivery-schedules` (route.manage) `{routeId*, vehicleId?(route default), driverEmployeeId?(route default), scheduleDate*, slot:"Morning", plannedStartTime?("HH:mm"), remarks?}` -> 201; one schedule per route+date+slot (409)
- `PUT /api/delivery-schedules/{id}` (route.manage) `{vehicleId?, driverEmployeeId?, scheduleDate*, slot*, plannedStartTime?, remarks?}`; date/slot only changeable while Planned with no deliveries; changing the driver re-assigns Pending stops
- `DELETE /api/delivery-schedules/{id}` (route.manage) soft delete; 422 if deliveries are attached

DeliveryListDto = `{id, deliveryNumber, salesOrderId, orderNumber, customerId, customerName, customerMobile, addressText, deliveryInstructions, deliveryDate, deliverySlot, deliveryScheduleId, routeId, routeName, driverEmployeeId, driverName, assignedUserId, assignedUserName, sequenceNo, status, dispatchedDate, deliveredDate, failureReason, orderTotal, totalQuantity, invoiceId, remarks}`
DeliveryDetailDto = DeliveryListDto + `{lines:[OrderLine as in orders], confirmation:{id, deliveryId, confirmedBy, confirmedByName, confirmedDate, outcome, deliveredQuantity, receivedBy, collectedAmount, latitude, longitude, failureReason, remarks} | null}`

- `GET /api/deliveries` (delivery.view; Driver role = only deliveries assigned to their user id, or to their employee id) query `date`(order delivery date), `status, routeId, driverEmployeeId, scheduleId, slot, customerId, search`; sortBy `id,deliveryNumber,orderNumber,customerName,deliveryDate,deliverySlot,status,sequenceNo,routeName`
- `GET /api/deliveries/my?date=yyyy-MM-dd` (delivery.view) driver view, not paged -> `DeliveryListDto[]` (default today, excludes Cancelled, ordered by slot/schedule/sequence)
- `GET /api/deliveries/pending-orders` (delivery.view; not Driver/Customer) query `from, to`(delivery date), `slot, routeId, customerId, search, page...` -> `PagedResult<OrderListDto>` of Pending/Confirmed/Failed orders with no live delivery (default deliveryDate asc)
- `GET /api/deliveries/{id}` (delivery.view; drivers own only) -> `DeliveryDetailDto`
- `POST /api/deliveries` (delivery.update; sp_CreateDelivery) `{salesOrderId*, deliveryScheduleId?, driverEmployeeId?, assignedUserId?}` -> 201 `DeliveryDetailDto` (order becomes Scheduled; driver/route default from schedule/route; assignedUserId defaults to the driver's login)
- `POST /api/deliveries/bulk` (delivery.update) `{deliveryScheduleId*, salesOrderIds*:[..], driverEmployeeId?, assignedUserId?}` -> 200 data `{requestedCount, createdCount, failedCount, created:[{salesOrderId, deliveryId, deliveryNumber}], failed:[{salesOrderId, message}]}`
- `POST /api/deliveries/{id}/dispatch` (delivery.update; drivers own only; sp_DispatchDelivery) no body -> `DeliveryDetailDto` (order Dispatched, schedule Dispatched)
- `POST /api/deliveries/{id}/confirm` (delivery.confirm; sp_ConfirmDelivery) body optional `{isDelivered:true, receivedBy?, remarks?, failureReason?(required when isDelivered=false), latitude?, longitude?}` -> `DeliveryDetailDto`. `p_IsPrivileged` = user has delivery.update AND is not the Driver role (the seeded Driver role also holds delivery.update, so drivers are always checked against the assigned user, or against their employee id when no user was assigned). Order becomes Delivered/Failed; schedule Completed when all stops are done.

## Billing

InvoiceListDto = `{id, invoiceNumber, customerId, customerName, customerCode, customerMobile, customerGstNumber, invoiceType, invoiceDate, dueDate, periodFrom, periodTo, subTotal, taxAmount, discountAmount, totalAmount, paidAmount, balanceAmount, status, isOverdue, orderCount, issuedDate, cancelledDate, cancelReason, remarks, createdDate}`
InvoiceDetailDto = InvoiceListDto + `{lines:[{id, salesOrderId, orderNumber, deliveryId, productId, description, quantity, unitPrice, discountAmount, taxPercent, taxAmount, lineTotal}], payments:[{id, customerPaymentId, paymentNumber, paymentDate, paymentModeName, referenceNo, amount, allocationDate}]}`

- `GET /api/invoices` (invoice.view; own only) query `customerId, status(Issued|PartiallyPaid|Paid|Cancelled|Draft|Overdue), from, to`(invoice date), `search`; sortBy `id,invoiceNumber,customerName,invoiceDate,dueDate,totalAmount,balanceAmount,status`; default invoiceDate desc
- `GET /api/invoices/{id}` (invoice.view; own only) -> `InvoiceDetailDto`
- `POST /api/invoices` (invoice.create; sp_GenerateInvoice) `{customerId*, periodFrom?, periodTo?(both required when no salesOrderIds), salesOrderIds?:[..]}` -> 201 `InvoiceDetailDto` (bills Delivered, un-invoiced orders; Consolidated when more than one order; due date = today + customer creditDays)
- `POST /api/invoices/{id}/cancel` (invoice.create) body optional `{reason?}` -> `InvoiceDetailDto`; only Issued invoices with no payments (422 otherwise); orders/deliveries are un-linked and the customer balance is reversed

PaymentListDto = `{id, paymentNumber, customerId, customerName, customerCode, invoiceId, invoiceNumber, paymentDate, amount, allocatedAmount, unallocatedAmount, paymentModeId, paymentModeName, referenceNo, status, receivedBy, receivedByName, remarks, createdDate}`

- `GET /api/payments` (custpayment.view; own only) query `customerId, invoiceId, paymentModeId, status, from, to`(payment date), `search`; sortBy `id,paymentNumber,customerName,paymentDate,amount,status,createdDate`; default paymentDate desc

- `POST /api/payments` (custpayment.create; sp_RecordCustomerPayment) `{customerId*, paymentDate?(today, not future), amount*(>0, 2 dp), paymentModeId*, referenceNo?(mandatory for modes that require it), invoiceId?(allocate only to it; default oldest open invoices first), remarks?}` -> 201 `PaymentDetailDto` (any remainder stays as `unallocatedAmount` credit; cash entry is written by the procedure)
- `GET /api/billing/outstanding?customerId=` (invoice.view OR custpayment.view; customers always own) -> `OutstandingRow[]` (not paged; only customers with open invoices): `{id(customerId), customerCode, customerName, customerType, mobile, creditLimit, openInvoices, oldestDueDate, currentAmount, days1To30, days31To60, days61To90, over90Days, totalOutstanding, unallocatedCredit}`
- `GET /api/billing/summary` (invoice.view OR custpayment.view; customers scoped to own) -> `{invoicedThisMonth, collectedThisMonth, collectedToday, totalOutstanding, overdueAmount, openInvoices, overdueInvoices, unallocatedCredit, uninvoicedOrders, uninvoicedAmount, currentAmount, days1To30, days31To60, days61To90, over90Days}`

## Audit
Writes to `AuditLog` (stored procedures of this group do not): Create/Update/Activate/Deactivate on masters, plus `Assign|Resolve|Close|Feedback` (complaints), `Pause|Resume|Cancel` (subscriptions), `Cancel` (orders, invoices), `Dispatch|Confirm` (deliveries), `Payment` (customer payments), `Create` for generated invoices/orders/deliveries.
